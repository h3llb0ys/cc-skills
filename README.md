# cc-skills

Скиллы для Claude Code.

## Установка

```bash
git clone https://github.com/h3llb0ys/cc-skills.git
cp -R cc-skills/skills/<имя> ~/.claude/skills/
```

## Скиллы

### consilium

Совет консольных агентов для внешнего ревью и выработки решений: codex CLI (GPT),
Claude-сабагенты, cursor-agent (grok). Два режима — ревью артефакта (код, архитектурное решение,
план, спека) и дизайн-совет, где участники предлагают решения, перекрёстно ревьюят и итеративно
улучшают выбранное.

Кроме механики запуска описывает протокол цикла целиком: сбор требований до старта участников,
проверку утверждений по коду, раунды верификации и совещание до консенсуса, адвоката дьявола
и премортем, кворум в финале, ревью итогового документа и сборку пакета передачи. Отдельно —
как вести долгий цикл: журнал и реестр прогонов, чтобы он пережил перезапуск сессии, чекпоинты
по объёму, счётчики вырождения и правила правки самого скилла.

#### Что можно попросить

N — число участников, по умолчанию 3.

| Формулировка | Что запускается | Цена |
|---|---|---|
| «проревьюй через codex/opus/grok» | один участник, без раундов | 1 вызов, 5–15 мин |
| «ревьюй до устранения замечаний», «я поправлю — проверишь снова» | итеративное ревью: тот же участник смотрит каждую новую редакцию | 1 вызов на итерацию, дефолт 4 |
| «консилиум», «второе мнение» | N участников параллельно и сведённый вердикт | N вызовов, 10–15 мин |
| «консилиум с xhigh», «добавь grok» | тот же цикл, другой состав или уровень reasoning | N вызовов |
| «полный консилиум», «пусть проверят друг друга» | плюс раунды верификации: свежие сессии голосуют по анонимным находкам | ×K вызовов |
| «пусть обсудят», «до консенсуса» | плюс совещание: живые сессии, адресные вопросы, снятие противоречий | +до 3×N |
| «с адвокатом дьявола» | плюс атака на консенсус — по возможности моделью другого вендора | +1 и больше |
| «пусть поищут, что выкинуть», «слишком раздулось» | упроститель: прогон против объёма решения, а не против ошибок | +1 |
| «A или B?», «стоит ли вернуть решение X» | вопрос по развилке: оба варианта уже названы, нужен выбор | N вызовов, 10 мин |
| «с премортемом» | плюс сценарии провала решения через полгода | +1 и больше |
| «дизайн-консилиум», «пусть предложат решения» | участники предлагают решения, перекрёстно ревьюят, выбирают лучшее и дорабатывают | 2N + итерации, часы |

Комбинируются свободно: «консилиум с xhigh, с адвокатом и премортемом», «дизайн-консилиум
в 10 раундов». Что не названо явно — скилл уточнит вопросом; в фоновом запуске, где спросить
некого, берёт дефолт и помечает это в вердикте.

```
skills/consilium/
├── SKILL.md                     # хаб: выбор модели, каркас вызова, ревью кода и документов
├── references/
│   ├── chair.md                 # роль председателя: требования, проверка фактов, вопросы заказчику
│   ├── cycle-state.md           # состав и дефолты, лог цикла, реестр прогонов, тайминги, восстановление
│   ├── deliberation.md          # раунды, совещание, итеративное ревью, адвокат, упроститель, премортем
│   ├── design.md                # дизайн-совет: этапы 0–5
│   ├── finalization.md          # кворум, ревью итогового документа, пакет передачи
│   └── maintenance.md           # как править сам скилл: волны, круг по патчу, шесть правил
└── scripts/
    ├── codex-run.sh             # запуск codex-участника (read-only, промпт из файла)
    └── cursor-run.sh            # запуск cursor-участника (grok)
```

Состав по умолчанию — два участника на codex (`gpt-5.6-sol`, `gpt-5.5`) и один Claude-сабагент,
все на high. Требуется установленный `codex` CLI; `cursor-agent` — только если в составе grok.

### premortem

Приём Клейна (prospective hindsight): вместо «что может пойти не так» решение объявляется
**уже провалившимся**, и модель объясняет, как именно. Смена рамки заставляет называть конкретные
механизмы отказа — режим рассказа даёт более честный результат, чем режим оценки, и снимает
дефолтную склонность соглашаться.

Скилл срабатывает сам, когда вот-вот прозвучит рекомендация с дорогим откатом: выбор архитектуры,
план миграции, зависимость с глубокой интеграцией, рефакторинг на три файла и больше, паттерн
на весь проект. На баг-фиксах, вопросах «как это работает» и уже принятых решениях не срабатывает —
там ритуал только шумит.

Что делает: объявляет запуск одной строкой (можно отказаться), собирает контекст из репозитория,
подбирает горизонт под тип решения, выдаёт список отказов, где у каждого — история на два-три
предложения, допущение, которое его сделало возможным, и наблюдаемый сигнал. Итог — синтез:
самый вероятный отказ, самый опасный, главное непроверенное допущение, переписанный план
и чеклист перед стартом. Всё в чат, файлов на диск не пишет.

### dispute

Режим интеллектуального оппонента: `/dispute` или «покритикуй меня». Дальше в диалоге выводы
пользователя не принимаются за истину — разбираются скрытые допущения, приводятся контраргументы
и альтернативы, проверяется логика. Не спор ради спора и не токсичность: цель — ясность,
а не победа.

Отличие от премортема: премортем одноразовый и привязан к конкретному обязательству,
диспут — липкий режим на весь разговор про качество идеи. Скиллы знают друг о друге
и вместе не срабатывают.
