# GitLab MR

Секция **Merge requests** во вкладке **Info** справа показывает связанные с
тредом GitLab MR. По нажатию на номер открывается MR в GitLab.

Плагин проверяет текущую ветку при открытии треда, в том числе с закрытой панелью
Info. Если открытый MR один, он привязывается автоматически. Если их несколько,
секция предлагает выбрать нужный. Ссылки сохраняются за тредом, поэтому остаются
после смены ветки, её удаления и перезапуска bb. Автопоиск поддерживает MR внутри
одного GitLab-проекта.

Пока тред виден, плагин проверяет его раз в 3 минуты. Настройка
`refreshMinutes` задаёт интервал. Значение `0` оставляет проверку при открытии.

Плагин использует `git` и уже авторизованный `glab` на машине checkout.
`gitlab.com` поддерживается по умолчанию. Для своего GitLab добавьте hostname
в настройку **Дополнительные хосты GitLab** (`gitlabHosts`). Поддерживаются HTTPS и
SSH remotes без нестандартных портов. Плагин берёт сохранённую авторизацию
конкретного хоста из `glab auth login --hostname <host>`. Достаточно доступа
на чтение к проекту и CI.

| Статус | Цвет |
| --- | --- |
| Passed | Зелёный |
| Warning, успех с предупреждениями | Оранжевый |
| Failed | Красный |
| Merged | Фиолетовый |
| Closed, ожидание CI или недоступность статуса | Серый |

Включите **Показывать MR в списке тредов** (`showSidebarBadges`), чтобы рядом
с заголовком появились кликабельные номера MR в цвете статуса. Один MR размещается
после Jira-бейджа, несколько выводятся второй строкой. По умолчанию эта настройка
выключена. Список тредов использует сохранённые статусы, а обновление по-прежнему
запускается только для открытого треда.

Если GitLab недоступен, ссылка остаётся видна, а подсказка показывает последний
известный результат.

## Локальная разработка

Нужен bb 0.50.1 или новее. Из каталога плагина:

```sh
npm ci --include=dev
npm run typecheck
npm test
npm run build
bb plugin install .
```
