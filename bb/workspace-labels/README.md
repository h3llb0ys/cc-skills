# Workspace Tools

Подпись ветки или worktree под заголовком треда в стандартном списке BB.

## Установка

Из корня этого репозитория: `npm ci --prefix bb/workspace-labels`, затем
`bb plugin install ./bb/workspace-labels --yes`.
Из Git:
`bb plugin install 'git:https://github.com/h3llb0ys/cc-skills.git@main#bb/workspace-labels' --yes`.

Требуется BB 0.49+ с SDK 0.6.132+ и включённый Git-плагин для актуальной ветки.

## Настройки

**Скрывать main** скрывает подпись основной ветки репозитория (по данным Git;
если они недоступны, используется имя `main`). Имя отдельного worktree остаётся
видимым, в том числе в режиме «worktree + ветка». Остальные ветки не скрываются.
Настройка применяется сразу, включая предпросмотр:
`bb plugin config workspace-labels set hideMain true`.

Settings → Installed plugins → Workspace Tools → **Вид подписи окружения**:

- **А · Простая подпись** (по умолчанию): имя worktree с иконкой папки Git или текущая ветка с иконкой ветки.
- **Б · Бейджи**: та же подпись в компактной рамке.
- **В · Worktree + ветка**: имя worktree и текущая ветка на отдельных строках.

Выбор применяется ко всем окнам сразу, без перезагрузки. CLI:
`bb plugin config workspace-labels set layout subtitle` (также `badges`, `details`).

Под настройками находится живой предпросмотр с условными тредами, ветками и
одной/несколькими задачами DEMO. Он следует выбранным настройкам; ползунок
«Ширина примера» позволяет увидеть переход между одной и несколькими строками.
Предпросмотр не читает реальные треды и не меняет ширину настоящего сайдбара.

**Собирать в одну строку, когда хватает места** включено по умолчанию.
Короткая подпись помещается рядом с заголовком и Jira-ссылками только тогда,
когда все они видны целиком. При сужении сайдбара, изменении заголовка или задач
подпись возвращается вниз. Измерение учитывает место для кнопок действий.
Двухстрочный вариант «worktree + ветка» и строки с метаданными других плагинов
сохраняют размещение снизу. Отключение настройки всегда оставляет подпись снизу:
`bb plugin config workspace-labels set autoInline false`.

В BB должны быть включены эксперимент `threadRowMetadata` и Organize → Rows → Metadata:
`bb settings experiment threadRowMetadata true` и `bb thread-list prefs set showRowMetadata true`.

Плагин использует публичный metadata slot и общий keyed-query Git-плагина.
Ветка обновляется по данным Git; при недоступности Git подсказка отмечает данные BB как неподтверждённые.
Отдельные worktree определяются по `environment.isWorktree`, а не по имени ветки или каталога.
Для detached HEAD показывается короткий SHA. В тредах без Git подписи нет.

## Завершение работы

В меню строки треда через **Customize actions** можно закрепить
**Архивировать и очистить** или **Удалить и очистить**.
Плагин удаляет worktree через Git на машине треда, затем закрывает тред
и удаляет его локальную ветку. Если Git не удалил worktree, история треда
сохраняется. Если BB не подтвердил закрытие, ветка сохраняется. Для управляемого BB worktree
с `.bb-env-teardown.sh` используется штатная архивация BB: действие очистки
оставляет его открытым, чтобы BB мог выполнить скрипт при удалении.

При изменениях в рабочих файлах, наличии игнорируемых файлов, невлитых коммитах или постоянном удалении
истории сначала открывается подтверждение. Для проверки коммитов используется
известная локально целевая ветка. После squash merge исходные коммиты могут
потребовать подтверждения. Основная ветка репозитория и `main` защищены.
Очистка защищает рабочие каталоги других активных тредов и исходники плагинов BB,
установленных с диска. При незавершённой операции Git или файлах, которые Git
исключил из проверки изменений, очистка останавливается.
Удаление каталога также убирает файлы, игнорируемые Git. Ветки на remote не затрагиваются.

## Совместимость с Jira

Jira Thread Links продолжает владеть всеми задачами треда: одной или несколькими.
Workspace Tools не читает и не меняет Jira-привязки, текст заголовка и ссылки.
Адаптивный слой измеряет существующую строку и добавляет собственные CSS-классы,
не перемещая и не копируя React-узлы в живом списке. Если все элементы помещаются,
несколько Jira-ссылок также собираются в одну строку. Иначе действует прежняя раскладка Jira.
Все три вида меняют только собственное содержимое в metadata slot. В режиме бейджей
Jira-задачи не копируются в строку окружения: они сохраняют своё существующее отображение.
Несколько тредов в одном worktree могут иметь разные наборы Jira-задач.

Альтернативный сайдбар должен поддерживать `experimental_ThreadRowMetadata`.
Автоматическое размещение рядом с заголовком работает только с разметкой
стандартного Thread list BB; при неизвестной структуре остаётся metadata slot.
Нативная строка метаданных общая с другими metadata-плагинами; длинные имена сокращаются,
полный путь и ветка доступны по наведению.
