# MR cycle

Код MR пишется целиком и без коммита, потом полируется восемью этапами — **каждый отдельным
проходом по диффу с коротким отчётом**. В одном общем проходе ревью вытесняет упрощение, тесты
не сверяются с пирамидой, а комментарии правятся раньше, чем устоялся код; отдельные проходы
ловят то, что общий пропускает.

## Режимы

| Ситуация | Что делать |
|---|---|
| Команда на код MR | прочитать документ плана MR и спеку (по ссылкам из запроса и плана; спеки нет — работать по плану), этап 0, затем этапы 1–8 |
| Владелец поправил дифф после цикла и просит ревью или правки | прочитать `rerun.md`: полный цикл заново |
| В дереве правки, не относящиеся к MR (документы плана и спеки к ним не относятся) | спросить до начала работы |
| По документу работать невозможно | спросить |

## Правила

- **Не коммитить и не пушить** — владелец смотрит и коммитит сам.
- Это исполнение согласованного плана: процессные скиллы с согласованием дизайна не запускать.
- Этапы цикла — не этапы плана: весь MR — один этап плана. Этапы цикла идут подряд, без пауз;
  свой план реализации пишешь в чат и ответа не ждёшь. Останавливаешься только на вопросах
  из «Режимов» и на итоговом отчёте.
- Перед стартом заново `git status` и `git log` — снимок из начала сессии устаревает. Если upstream
  ветки — main, снять: `git branch --unset-upstream`.
- Документы плана и спеки только читать; где документ расходится с соседями, главнее документ.
  Расхождение документа с кодом — сразу в чат, работа идёт по документу.
- Не переоткрывать решения из плана, спеки, памяти проекта и отклонённое на прошлых итерациях.
- Проверки (команды — из CLAUDE.md и памяти проекта): после этапа, менявшего файлы, — сборка, vet
  с тегами, линт, юнит-тесты затронутых пакетов; интеграционные наборы, покрывающие изменённый
  код, — после этапов 0 и 5, после правки SQL или фикстур и после последней правки цикла.
- Язык и формат комментариев — по CLAUDE.md и памяти проекта.
- Вызов цикла — явное разрешение на агентов этапа 8.

## Этапы

| № | Этап | Готово, когда |
|---|---|---|
| 0 | Код файл за файлом по образцу 2–3 соседних пакетов того же слоя, юнит-тесты на новые ветки, генерация штатным генератором | всё зелёное, в диффе генерации только ожидаемое |
| 1 | Ревью: баги, null и пустые значения, границы, совместимость контракта, ошибка без частичного результата, неточные комментарии | каждое замечание проверено по коду и исправлено |
| 2 | Упрощение: приватную обёртку с одним вызовом — инлайн; дубли — по шаблону соседей; таблицы соответствий, которые план держит явными, не выводить из соглашения об именах | убрать нечего без потери смысла |
| 3 | Стиль и архитектура против соседей того же слоя: раскладка по файлам, имена, логи и ошибки, импорты, длина строк, место типов и proto-сообщений | расхождений с соседями нет |
| 4 | Пирамида: листовые функции — все ветки и краевые значения; верхний тест — только своя склейка. Вопрос к каждому: «какую ветку ЭТОЙ функции он ловит сверх нижнего?» Кейс, который план требует наверху, — на нижний уровень (если там его нет) и сообщить | верхних дублей нет |
| 5 | Интеграционные кейсы в набор проекта (каталог — из запроса, CLAUDE.md или памяти): чем больше разных кейсов, тем проще потом рефакторить. На каждое новое поведение — сквозной кейс в каждом харнессе набора, где оно проверяется, плюс сценарии смысла: оси, окна, роли, изоляция, пустые значения, сочетания | фикстуры дают ненулевые значения, кейсы лежат в группах, которые запускает CI, прогон с `-v` показывает их выполнение; README набора обновлён, если он описывает фикстуры |
| 6 | Комментарии: собрать все добавленные (код, proto, SQL), сократить, оставить причины и неочевидную семантику; правка doc-комментария proto — перегенерировать | ни один не врёт и не пересказывает код |
| 7 | Повторное ревью и исправление — как этап 1, свежим взглядом по всему диффу | каждое замечание проверено по коду и исправлено, имена тестов совпадают с проверками, всё зелёное |
| 8 | Внешний ревьюер без контекста — прочитать `reviewer.md` | по `reviewer.md` |

## Итоговый отчёт

Сначала снимок для повторного прогона: отклонённое с причинами — в файл в scratchpad, затем в корне
репозитория `bash <каталог скилла>/scripts/snapshot.sh save <файл>`. Скрипт копирует изменённые и
новые файлы в `~/.claude/mr-cycle/`; репозиторий он не меняет.

Отчёт: по этапам — что сделано и исправлено; находки внешних ревьюеров — принятые и отклонённые с
причинами; отступления от плана и от скилла; какие проверки зелёные и что не запускалось; что
вынести в описание MR; путь снимка. Последние слова — «ничего не закоммичено».

## Красные флаги

| Мысль | На деле |
|---|---|
| «Просили только ревью» — после того как владелец поправил дифф | Прочитать `rerun.md`: полный цикл заново |
| «Этапы похожи, пройду всё за раз» | Каждый этап — отдельный проход и отчёт |
| «План требует этот тест» | Пирамида важнее плана: перенести вниз и сообщить |
| «Ревьюер прав» или «помню, что это не так» | Проверить по коду, а не по памяти |
| «Тот же агент быстрее» | Каждая итерация — новый агент |
| «Всё зелёное — можно закоммитить» | Коммитит владелец |
