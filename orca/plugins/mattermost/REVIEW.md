# Два цикла ревью Mattermost / Orca

База: main `b204f795663403d54947483593e7b8317701c452` плюс исходная реализация
плагина в рабочем дереве. Перед началом содержимое scoped paths в main и worktree
совпало; чужих изменений или staged files в этих путях не было. Правила:
`review/SKILL.md`; каждый дефект ниже имеет сценарий и регрессионную проверку.

## Цикл 1

1. **P1 — проверка соединения теряла новую cookie.** После «Проверить соединение»
   поле очищалось; «Сохранить» на новой настройке падало, а при замене сессии могло
   оставить старую cookie. Исправлено в `src/panel.tsx`: очищать только после
   успешного сохранения. Тест `testing a fresh cookie preserves it until Save succeeds`
   сначала падал с `actual: ''`, затем прошёл.
2. **P1 — большие входящие ломали загрузку панели.** Bridge возвращал 100 полных тел
   и черновиков. Fixture из 100 сводок дал 8 024 992 байта, больше лимита worker;
   обрезка текста уже в UI происходила слишком поздно. В `scripts/bridge.py` добавлены
   страницы по 10 сводок и превью по 2000 символов до передачи worker. UI умеет
   предыдущую/последнюю страницу; копирование читает полный черновик из SQLite.
   Регрессии проверяют размер ответа, обход всех 100 записей без потерь и реальные
   кнопки пагинации/копирования в native test runtime.
3. **Проверки чистой установки зависели от локального runtime.** Существующий тест
   копировал игнорируемый `runtime/` из рабочего каталога и падал на чистом clone.
   Теперь тест создаёт чистый layout репозитория без runtime, выполняет `prepare.py`,
   переносит пакет отдельно от repo и запускает его bridge. При разработке bridge
   выбирает актуальный canonical source, а установленная копия — свой runtime.

После исправлений: 86 Python tests, 4 plugin tests и TypeScript проходили.
Дерево цикла 1 зафиксировано отдельным локальным snapshot перед вторым чтением diff.

## Цикл 2

Повторно проверены изменения цикла 1, затем scheduler/precheck/manual dispatch,
редактирование, пауза, delivery receipt, окончание срока и достижимость действий UI.

1. **P2 — повторный разбор до окончания lease.** При интервале 5 минут незавершённый
   Orca batch снова давал precheck exit 0 через 301 секунду, хотя lease ещё действовал.
   Это запускало лишнего агента; атомарный resolve защищал от повторной доставки,
   но не от лишнего разбора. `batch_waiting` учитывает Orca lease; ручная проверка
   возвращает busy. Timeout ручного запуска считается неопределённым результатом:
   повтор ждёт lease, а подтверждённая ошибка допускает retry. Регрессии проверяют
   scheduled/manual пути до и после истечения lease.
2. **P1 — нельзя остановить частично зарегистрированную подписку.** Если расписание
   создано, но его ID не сохранился, pause отвергал `schedule=None` до записи guard.
   Теперь Orca pause сначала сохраняет suspended и отзывает receipt, затем ищет
   расписание по watch name и отключает его. При ошибке discovery локальная пауза
   остаётся действующей. Для BB прежнее требование schedule сохранено.
3. **P2 — UI показывал старое состояние после частичной ошибки pause.** Backend уже
   записал suspended, но ошибка scheduler прерывала refresh; пользователь продолжал
   видеть «Пауза» вместо «Возобновить». Действия обновляют данные в finally, сохраняя
   сообщение ошибки. Native regression моделирует именно эту частичную запись.
4. **P2 — истёкшую подписку нельзя было повторить из панели.** Создание того же
   binding отвергалось, редактор для ended был отключён, удаления не было.
   Добавлено удаление завершённой подписки с отдельным подтверждением и platform
   guard. Входящие читаются по сохранённой platform и не исчезают после удаления
   watch. Тест проходит expiry → подтверждение/unwatch → новый watch с тем же
   источником и сохранённой историей.

Дополнительно проверены пауза и edit во время отпущенного write lock ручного dispatch:
старые receipts отвергаются, новые настройки не затираются. Сводка и receipt остаются
атомарными при ошибке доставки; BB-записи недоступны всем мутирующим действиям панели,
включая удаление. Новых незакрытых дефектов в проверенных путях не осталось.

Отдельная чистая копия без `.orca`, `runtime`, `node_modules` и `__pycache__`:

  тесты проходят до подготовки runtime.
- `prepare.py`: пакет собран; тест переносит его за пределы repo и сверяет общие скрипты.
- `orca plugin types`, `test`: **6 passed**.
- `orca plugin check`: populated, empty, paused, expired, broken, failed — без issues/warnings.
- `orca plugin validate`: passed.
- TypeScript 7.0.2 / @types/node 26.6.11: passed с generated Orca types.
- `git diff --check`: passed.

Установка из UI и живой аккаунт не использовались; все API/scheduler/delivery/clipboard
заменены mock, SQLite — временная. Native controls проверены через SDK runtime.

Установленная копия плагина не обновлялась. Для установки нужен `prepare.py` и явное
одобрение trusted worker пользователем. Это оставшиеся внешние проверки, не скрытые
блокеры публикации исходников.
